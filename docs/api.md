## Общие правила

Заголовки:

| Заголовок | Когда | Значение |
| --- | --- | --- |
| `X-Max-Init-Data` | `prod` | Сырая строка `window.WebApp.initData` из MAX; проверяется подпись и возраст ([architecture.md](architecture.md#подписанный-initdata-режим-prod)) |
| `X-Client-Id` | только `demo` и `sandbox` | Строка `^[A-Za-z0-9_-]{8,64}$`. В `demo` все значения дают одного общего пользователя, в `sandbox` каждое значение - отдельный пользователь. В `prod` игнорируется |
| `Content-Type: application/json` | запросы с телом | |

Все маршруты, кроме `GET /api/health`, требуют авторизации (иначе `401`).

Формат ответов: JSON. Мутации возвращают `{"state": <состояние>}` (структура состояния - [architecture.md](architecture.md#состояние-apistate)), иногда с дополнительным полем. Ошибка: `{"detail": "<текст>"}`.

Общие коды ошибок:

| Код | Когда |
| --- | --- |
| 400 | нарушено правило предметной области (текст в `detail`) |
| 401 | нет или недействительна авторизация |
| 403 | недостаточно прав |
| 404 | объект не найден или недоступен вызывающему |
| 422 | тело или параметры не прошли валидацию схемы (стандартный формат FastAPI) |
| 429 | сработал лимит ([architecture.md](architecture.md#ограничения)) |
| 500 | не удалось сгенерировать код |

Кто вызывает: проверка прав выполняется на сервере; роль указана по коду сервисного слоя. Роль «директор» означает директора школы, которой принадлежит объект.

## Системные

| Метод и путь | Кто | Параметры | Ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `GET /api/health` | без авторизации | - | `{"status":"ok","mode":"prod\|demo\|sandbox"}`; в sandbox добавляется `boot_id` (идентификатор жизни базы) | - |
| `GET /api/state` | любой авторизованный | - | полное состояние зрителя | 401 |
| `POST /api/max/webhook` | только MAX, заголовок `X-Max-Bot-Api-Secret` | JSON-обновление MAX (`bot_started`, `message_created`; остальное игнорируется), до 64 КиБ | `{"ok":true}`; сообщение боту уходит в фоне | 403 секрет не задан или неверен, 400 не JSON, 413 тело велико, 404 не `prod`. См. [bot.md](bot.md) |

`GET /api/state` при первом обращении создаёт пользователя; для директора может дописать недостающие коды классов.

## Школы и регистрация

| Метод и путь | Кто | Параметры / тело | Ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `POST /api/school/check-code` | любой | `{code: <=32}` (в теле, а не в URL: код не попадает в журналы доступа) | найден: `{valid:true, kind:"student\|teacher", class_id, class_name, school_name, city, teacher_name, invite_code}`; не найден: HTTP 200 `{valid:false, detail}` | 429 после 20 неверных кодов за 10 мин |
| `GET /api/school/catalog` | любой | query `city` (точное совпадение), `q` (подстрока названия без учёта регистра), `limit` (1-500, по умолчанию 500; форма ученика берёт 20), `offset`, `only_cities` (bool) | `{cities:[], schools:[{id,name,city}], classes:[{id,school_id,name}], total, has_more}`; только активные школы, без кодов. `cities` заполняется только без `city`/`q` или при `only_cities` (до 500) | - |
| `GET /api/school/cities` | любой | query `q` (подстрока без учёта регистра, пусто = самые крупные), `limit` (1-20, по умолчанию 10) | `{cities:[{name, schools}], total}`; только города активных школ (pending и rejected не видны); сначала города, начинающиеся с запроса, затем по числу школ | - |
| `POST /api/school/join` | ученик (код ученика или `class_id`); любой, кроме директора (код педагога) | `{invite_code?: str<=32, class_id?: int}` | `{class_id, state}` | 400 нет ни кода, ни класса; 400 директор вводит код педагога; 403 ученик, уже состоящий в классе, вводит код педагога; 403 не ученик вступает по коду ученика/`class_id`; 404 неверный код или неактивный/несуществующий класс; 429 |
| `PATCH /api/school/classes/{class_id}` | директор школы этого класса | `{name?: 1-12, weekly_goal?: 100-20000}` (хотя бы одно поле) | `{state}` | 400 пустой запрос, невалидное имя, имя уже есть в школе (без учёта регистра); 404 чужой/несуществующий класс (в том числе для педагога и ученика); 422 схема. Коды класса не меняются |
| `POST /api/school/create` | пользователь без класса или уже директор; в `demo` нельзя | `{name: 3-80, city: 2-60, classes: [{name: 1-12, weekly_goal?: 100-20000 (=1600, из формы не передаётся)}] (1-40)}` | `{school_id, state}`; создающий становится директором | 400 валидация/дубликат школы/повтор класса; 403 `demo`, уже 3 школы или пользователь состоит в классе («Вы уже состоите в классе»); 429 (5 попыток в час) |
| `POST /api/school/{school_id}/classes` | директор школы | `{name: 1-12, weekly_goal?: 100-20000 (=1600)}` | `{state}` | 400 валидация, повтор названия, больше 60 классов; 403 школа отклонена администратором; 404 не ваша школа или `demo` |
| `POST /api/school/{school_id}/select` | директор школы | - | `{state}` | 404 |
| `DELETE /api/school/classes/{class_id}` | директор школы класса | - | `{state}` | 400 в классе есть ученики/педагоги, задания (и значит работы) или история XP; 403 школа отклонена; 404. Запреты на вступление (`class_exclusions`) и привязки каталога (`class_staff`) удаляются вместе с классом |
| `POST /api/school/classes/{class_id}/codes` | директор школы класса | `{kind: "student"\|"teacher"}` | `{state}`; новый код вместо старого | 400 неизвестный тип; 404 |
| `POST /api/admin/schools/{school_id}/status` | администратор платформы | `{status: "active"\|"rejected"}` | `{state}` | 400 неизвестный статус; 403 не администратор; 404 нет школы. `active` возвращает и ранее отклонённую школу. Отклонённая школа: директор видит её, но не меняет классы и коды (403); её классы не принимают новых учеников и педагогов (код и `class_id` не находятся); в её классах нельзя создавать задания, сдавать, проверять работы и начислять XP (403 с пояснением) |

Замечания:

- Код (`invite_code`) ищется без учёта регистра и дефиса; кириллические двойники латинских букв нормализуются. Код педагога проверяется после кода ученика. Классы школ не в статусе `active` кодом не находятся.
- `POST /api/admin/schools/{id}/status` принимает любую школу, не только `pending`.
- Создание школы переводит аккаунт в роль директора, сбрасывает `class_id` и ставит `onboarded=1`.

## Профиль и магазин

| Метод и путь | Кто | Тело | Ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `POST /api/profile/name` | любой авторизованный | `{first_name: 2-24, last_name?: <=32}` | `{state}` | 400/422 длина или символы (только буквы, пробел, дефис, точка, апостроф). Имя из одного поля «Имя Фамилия» делится по первому пробелу. После этого имя блокируется: данные MAX его больше не перезаписывают |
| `POST /api/onboarding` | любой авторизованный | `{first_name: 2-24, last_name?: <=32, avatar?: {ключ: id}, invite_code?: <=32, class_id?: int}` | `{state}` | 400 имя, образ, предмет не открыт/не куплен; 400 директор вводит код педагога; 404 неверный код/класс; 429 |
| `POST /api/avatar/equip` | любой | `{key, item_id}` | `{state}` | 400 неизвестное поле, предмета нет, не куплен, не открыт уровнем |
| `POST /api/shop/buy` | любой | `{item_id}` | `{state}` | 400 предмет не найден, бесплатный, уже куплен, мало уровня или искр |

`state.teacher.excluded` - исключённые из своего класса (до 100): `[{id, name, reason, removed_at}]`. `state.viewer.removed_from` - `{class_name, school_name}` для ученика без класса, которого исключили (иначе `null`).

Пока запрет есть, вступление в этот класс отвечает `403 «Вы отчислены из этого класса. Обратитесь к педагогу.»`: `/api/school/join` (по `class_id` и по коду ученика), `/api/onboarding`; `POST /api/school/check-code` возвращает `valid: false` с тем же текстом в `detail`. Другие классы и код педагога запретом не затрагиваются.

`state.viewer.needs_name` - `true` только у педагога и директора, у которых имя пустое или равно значению по умолчанию «Герой» (MAX не прислал имя) и не задано вручную; у ученика всегда `false`. Флаг `users.name_locked` ставится при вводе имени (онбординг или `/api/profile/name`).

`/api/onboarding`: сохраняет имя, образ, отмечает профиль заполненным. Класс берётся из `class_id` (без кода) или из `invite_code`; код педагога делает аккаунт педагогом. Имя из одного поля делится по первому пробелу на имя и фамилию, если `last_name` пуст. Для педагога и директора класс не меняется (кроме перехода ученика в педагоги).

Ключи `key` образа: `skin`, `hair`, `hairColor`, `outfit`, `accessory`, `frame`. Идентификаторы предметов - в `COSMETICS` (`backend/game.py`) и в `state.cosmetics`.

## Задания и проверка

| Метод и путь | Кто | Тело | Ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `POST /api/challenges/{id}/submit` | ученик | `{proof: 3-1000 после обрезки пробелов, proof_url?: http(s)-ссылка <=500; обязательна при proof_type=link}` | `{state, result:{status:"pending", challenge_title}}` | 400 нет класса, срок истёк, пустой/короткий/длинный ответ, ссылка не http(s) или длиннее 500, нет ссылки для `link`, уже на проверке/выполнено (в том числе при параллельной двойной отправке); 403 не ученик, чужой класс, школа отклонена; 404 нет задания |
| `POST /api/challenges` | педагог (свой класс), директор (классы своих школ) | `{title: 3-80, description?: <=320, category, xp: 10-300, kind, deadline?: "ГГГГ-ММ-ДД", subject?: <=60 ("Общее"), proof_type?: <=20, class_id?}` | `{state}` | 400 валидация (см. ниже); 403 не педагог/директор или чужой класс |
| `POST /api/challenges/{id}/archive` | педагог/директор класса задания | - | `{state}` | 403; 404 |
| `POST /api/reviews/{completion_id}` | педагог/директор класса | `{action:"approve"\|"reject", reason?: <=200}` | `{state, result}` | 400 уже проверено (в том числе проигравший из двух параллельных запросов: XP начисляется ровно один раз); 403 не педагог, заявка другого класса, собственная работа (кроме `demo`), автор не ученик, школа отклонена; 404; 422 неизвестное действие |
| `POST /api/reviews/batch` | педагог/директор | `{completion_ids: [id] (1-100), action: "approve"\|"reject", reason?: <=200}` | `{state, result:{action, approved, rejected, failed, total, counts:{approved, rejected, failed}, errors:[{id, detail, status}], results:[{id, success, result\|error}]}}` | 403 не педагог/директор; 422 неизвестное действие. Каждая заявка проверяется в своей транзакции; ошибки по отдельным заявкам (только ожидаемые, текстом для пользователя) попадают в `errors`, ответ остаётся 200. Повторы id учитываются один раз |
| `POST /api/teacher/students/{student_id}/remove` | педагог своего класса, директор школы класса | `{reason?: <=120}` | `{state}` | 400 не ученик, сам себя, ученик уже без класса; 403 ученик другого класса/школы или роль ученика; 404 нет такого пользователя. Ученик получает `class_id=NULL`, запись в `class_exclusions`; XP, покупки, герой и история заданий сохраняются |
| `POST /api/teacher/students/{student_id}/restore` | те же права | - | `{state}` | 404 нет запрета в ваших классах. Снимает запрет на вступление; в класс ученик не возвращается сам |
| `POST /api/teacher/reward` | педагог/директор класса | `{student_id, amount?: 10-300 (50), reason: 3-120 (обязательна)}` | `{state}` | 400 причина пустая; лимит: не больше 300 XP вручную одному ученику за сутки (МСК) от всех педагогов и не больше 3000 XP за сутки от одного педагога; 403 чужой класс, себе, школа отклонена; 404 ученик не найден; 422 нет причины |

Подробности:

- `class_id` в создании задания: по умолчанию класс вызывающего. Педагог может указать только свой класс.
- Валидация сервиса при создании задания: `category` из справочника, `kind` из справочника, `xp` - любое целое от 10 до 300 (схема API и сервис используют один диапазон; ручное начисление `/api/teacher/reward` - тот же диапазон 10-300), `deadline` не в прошлом (иначе 400), пустой срок - через 2 дня, `proof_type` не из `text|link|photo` заменяется на `text`.
- `result` проверки: при `approve` - `{status, student_name, xp_awarded, student_level, level_up}`; при `reject` - `{status, student_name, xp_awarded: 0}`.
- Подтверждение начисляет XP по награде задания и +5 искр; отклонение сохраняет причину, ученик может отправить задание повторно до срока. Отклонённое задание после срока отдаётся со статусом `expired` (причина в `reject_reason` сохраняется).
- Все целочисленные id в путях и телах ограничены 1..2^62 (иначе 422, а не 500); `offset` каталога 0..1 000 000.
- Действия, меняющие несколько строк (сдача, проверка, покупка, начисление, удаление класса), выполняются в транзакции `BEGIN IMMEDIATE`, условия (статус `pending`, баланс искр, лимиты) проверяются под блокировкой записи.
- Пакетная проверка не атомарна: часть заявок может пройти, часть - нет.
- `submit` для ученика с прошедшим сроком возвращает 400, для уже отклонённой заявки обновляет её и снова ставит `pending`.
- Ручное начисление: категория `homework`, +5 искр, обновляет серию.

## Справочники значений

- `category`: `homework` (Домашнее задание), `club` (Кружок или секция), `help` (Помощь однокласснику), `weekly` (Задание недели), `olympiad` (Олимпиада или конкурс), `event` (Школьное событие), `streak` (Серия дней).
- `kind`: `daily` (На сегодня), `weekly` (На неделю), `event` (Событие).
- `proof_type`: `text`, `link`, `photo`.
- Статус задания для зрителя: `available`, `pending`, `approved`, `rejected`, `expired`.
- Статус школы: `active`, `pending`, `rejected`.
- Режим: `prod`, `demo`, `sandbox`.
