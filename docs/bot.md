# Бот MAX

Когда пользователь нажимает «Начать» в чате с ботом, бот присылает короткое приветствие и кнопку «Открыть приложение». На любое сообщение в личном чате бот отвечает подсказкой с той же кнопкой, не чаще одного раза в `BOT_REPLY_INTERVAL` секунд (по умолчанию 60) на пользователя. В группах и каналах бот молчит.

Код: `backend/maxbot.py` (клиент и обработчик), `tools/max_bot.py` (управление подпиской), тесты `tests/test_maxbot.py`.

Источники фактов об API: документация платформы dev.max.ru (раздел `docs-api`: страницы POST /subscriptions, GET /subscriptions, DELETE /subscriptions, POST /messages, GET /me, Update, Keyboard) и OpenAPI-схема github.com/max-messenger/api-schema.

## Что подтверждено документацией

- Адрес API: `https://platform-api2.max.ru` (старый `platform-api.max.ru` документация не рекомендует). Нужно доверять сертификату Минцифры.
- Авторизация: заголовок `Authorization: <токен>`; токен в строке запроса не поддерживается.
- `GET /me`: поля `user_id`, `first_name`, `username` (может быть `null`).
- `POST /subscriptions`: тело `url` (только `https://`, порт только 443), `update_types`, `secret` (5-256 символов). Секрет MAX присылает в заголовке `X-Max-Bot-Api-Secret`. `GET /subscriptions` возвращает `subscriptions[]` с `url`, `time`, `update_types`. `DELETE /subscriptions?url=...`, ответ с полем `success`.
- Доставка: сервер должен ответить 200 за 30 секунд; при неудаче до 10 повторов (60 с, 150 с, 375 с, ...); если 8 часов нет успешного ответа, бот автоматически отписывается.
- Обновления: `bot_started` (поля `timestamp`, `chat_id`, `user.user_id`, необязательный `payload`) и `message_created` (`message.sender`, `message.recipient.chat_type` = `dialog` | `chat` | `channel`, `message.body.mid`).
- `POST /messages?user_id=<id>`: тело `text` (до 4000 символов) и `attachments` с `{"type":"inline_keyboard","payload":{"buttons":[[...]]}}`. Не больше двух сообщений в секунду в один диалог.
- Кнопка `open_app` (OpenAPI-схема): `text`, `web_app` (публичное имя бота, к которому привязано мини-приложение, обязательно), `contact_id` (user_id бота), `payload` (до 512 символов, `[\w-]*`). Страница Keyboard на dev.max.ru поля `open_app` не описывает - они взяты из OpenAPI-схемы.

## Что не подтверждено

- Поведение клиента MAX при нажатии `open_app` в вашем боте проверяется только вручную (см. «Проверка»).
- Допустимый набор символов секрета: в тексте страницы только латиница, цифры и дефис, в шаблоне также подчёркивание. Утилита генерирует только `0-9a-f`.
- `payload` у `bot_started` (диплинк) намеренно не обрабатывается, значение игнорируется.
- Если `GET /me` не вернул `username`, кнопка заменяется обычной ссылкой на `PUBLIC_URL`; она открывает сайт в браузере, а не мини-приложение внутри MAX.

## Настройка бота

1. Бот создаётся и настраивается на business.max.ru: «Чат-боты» - нужный бот. Токен: «Чат-боты» - меню бота - «Настройки» (документация, страница авторизации).
2. Мини-приложение должно быть привязано к этому боту в настройках платформы (кнопка использует username бота). Адрес мини-приложения: `https://m.ospab.org`.
3. Токен храните только в `.env` (`MAX_BOT_TOKEN`); в логи и ответы он не попадает.
4. Для доступа к API с сервера может понадобиться сертификат Минцифры. Если запросы к API падают с ошибкой проверки сертификата, добавьте сертификат в системное хранилище или укажите PEM-файл в `MAX_CA_BUNDLE`.

## Переменные окружения

См. таблицу в [configuration.md](configuration.md): `MAX_WEBHOOK_SECRET`, `MAX_BOT_USERNAME`, `PUBLIC_URL` (`MINIAPP_URL`), `MAX_API_BASE`, `MAX_CA_BUNDLE`, `BOT_REPLY_INTERVAL`.

## Порядок после деплоя

На сервере, из каталога проекта (`/opt/school-hero`):

1. Сгенерируйте секрет и впишите в серверный `.env` строку `MAX_WEBHOOK_SECRET=<значение>`:
   `python -c "import secrets; print(secrets.token_hex(32))"`.
   Если пропустить шаг, `subscribe` сам сгенерирует секрет и покажет строку для `.env`.
2. `systemctl restart school-hero`.
3. `python tools/max_bot.py me` - выводит имя и username бота.
4. `python tools/max_bot.py subscribe` - регистрирует `https://m.ospab.org/api/max/webhook` для `bot_started` и `message_created`. Если секрет был сгенерирован утилитой, добавьте выведенную строку в `.env` и снова перезапустите сервис (до этого webhook отвечает 403).
5. `python tools/max_bot.py status` - подписка должна быть в списке. `unsubscribe` снимает её.

Команды читают `.env` из корня проекта и не печатают токен.

## Проверка

1. Откройте чат с ботом и нажмите «Начать» (для повторной проверки удалите диалог и откройте заново). Должно прийти приветствие с кнопкой «Открыть приложение».
2. Нажмите кнопку: мини-приложение открывается внутри MAX.
3. Напишите боту любой текст: придёт подсказка с кнопкой (повторно не раньше чем через `BOT_REPLY_INTERVAL` секунд).
4. Журнал: `journalctl -u school-hero -n 100`. Токен и секрет в нём не пишутся.

## Устройство и безопасность

- `POST /api/max/webhook` не требует `initData`; защита - секрет в заголовке `X-Max-Bot-Api-Secret`, сравнение за постоянное время. Нет секрета в `.env` или он не совпал - 403. Вне `prod` маршрут отвечает 404.
- Тело ограничено 64 КиБ, неизвестные поля и типы обновлений игнорируются.
- Ответ 200 уходит сразу, сообщение отправляется в фоне: таймаут 10 с, до 3 попыток при сетевых ошибках, 429 и 5xx.
- Повторная доставка того же обновления (`bot_started` - по пользователю и `timestamp`, сообщение - по `mid`) не вызывает повторного ответа. Кэш в памяти процесса: после перезапуска сервиса он пуст.
- Адрес API берётся только из `MAX_API_BASE`.

## Типичные проблемы

| Симптом | Причина и решение |
| --- | --- |
| `subscribe` падает с HTTP 4xx/5xx | Проверьте токен и `PUBLIC_URL` (только `https://`, порт 443, сертификат доверенного центра с полной цепочкой); `curl -i https://m.ospab.org/api/health` снаружи |
| Ошибка `ConnectError` при вызовах API | Сервер не доверяет сертификату Минцифры: добавьте его в систему или задайте `MAX_CA_BUNDLE` |
| Приветствия нет, в журнале nginx `POST /api/max/webhook 403` | `MAX_WEBHOOK_SECRET` в `.env` не совпадает с секретом подписки или не задан, либо сервис не перезапущен. Выполните `unsubscribe`, затем `subscribe` |
| Запросы к webhook дают 404 | `APP_MODE` не `prod` или пуст токен |
| Бот молчит, подписки нет в `status` | MAX отписывает бота, если 8 часов нет ответов 200. Устраните причину и выполните `subscribe` |
| В журнале «не удалось отправить сообщение» | Смотрите код HTTP в записи: 401 - неверный токен, иначе сеть или сертификат |
| Вместо кнопки приложения ссылка | Не удалось получить username бота: задайте `MAX_BOT_USERNAME` |
| Кнопка есть, мини-приложение не открывается | Мини-приложение не привязано к боту либо `MAX_BOT_USERNAME` указывает на другого бота. Сверьте с `python tools/max_bot.py me` |
| На сообщения нет ответа | Сработал лимит `BOT_REPLY_INTERVAL`, либо это группа или канал |
