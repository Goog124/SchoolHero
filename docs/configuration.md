# Конфигурация

Настройки читаются из переменных окружения в `backend/config.py` (`Settings.from_env`). Файл `.env` в корне проекта подхватывается через `python-dotenv` при старте `app.py` и **не перезаписывает** переменные, уже заданные в окружении процесса.

## Режимы работы

Режим задаётся только `APP_MODE`. Пустой токен режим не переключает.

| | `prod` (по умолчанию) | `demo` | `sandbox` |
| --- | --- | --- | --- |
| Назначение | боевой сервер | витрина для показа | локальная проверка регистрации |
| Вход | подписанный `initData` из MAX (`X-Max-Init-Data`) | заголовок `X-Client-Id`, подпись не проверяется | заголовок `X-Client-Id`, подпись не проверяется |
| `MAX_BOT_TOKEN` | обязателен, иначе приложение не стартует | не нужен | не нужен |
| Пользователи | реальные, по MAX id | один общий выдуманный профиль для всех посетителей | каждый `X-Client-Id` - отдельный пользователь с ролью ученика |
| Данные | пустая база, школы создают директора (и необязательный `catalog.json`) | выдуманные школы, классы, ученики, педагог | пустая база, сохраняется между запусками (`npm run sandbox-wipe` стирает) |
| База по умолчанию | `school_hero.db` | `school_hero_demo.db` | `school_hero_sandbox.db` |
| Роли | реальные (регистрация, коды, списки id) | переключатель роли в интерфейсе (`/api/demo/role`) | реальные, как в prod; переключателя ролей нет |
| Регистрация школы | да | нет (403) | да |
| Демо-панель | нет | панель «Демо»: роль и сброс | панель «Песочница»: список тестовых пользователей |
| `/api/demo/*` | 403 | работает | 403 |
| Где запускать | сервер | только локально | только локально; `HOST` обязан быть `127.0.0.1`, `localhost` или `::1` |

В `GET /api/state` поле `mode` равно режиму, а `verified` - `true` только в `prod`.

Предупреждения:

- `demo` и `sandbox` входят без проверки подписи. Не публикуйте их.
- Проверка `HOST` в `sandbox` защищает только от запуска на не-loopback адресе. Если перед процессом стоит обратный прокси (nginx), а `HOST=127.0.0.1`, проверка пройдёт, и вход без подписи станет доступен снаружи. Не задавайте `APP_MODE=sandbox` на сервере.
- В `demo` и `sandbox` данные боевой базы не используются: путь к базе другой, а `DATABASE_PATH` с именем `school_hero.db` заменяется на файл режима; если база режима всё же указывает на `school_hero.db`, старт завершается ошибкой.

## Таблица переменных

| Переменная | Обязательна | По умолчанию | Описание |
| --- | --- | --- | --- |
| `APP_MODE` | нет | `prod` | `prod`, `demo` или `sandbox`. Любое другое значение - ошибка при старте. Регистр не важен. |
| `MAX_BOT_TOKEN` | да в `prod` | пусто | Токен бота MAX. Из него считается ключ HMAC для проверки `initData`. Пробелы по краям обрезаются. |
| `MAX_WEBHOOK_SECRET` | да для бота в `prod` | пусто | Секрет webhook бота MAX, 32-256 символов `[A-Za-z0-9_-]` (например `python -c "import secrets; print(secrets.token_urlsafe(32))"`). MAX присылает его в заголовке `X-Max-Bot-Api-Secret`. Пусто - `POST /api/max/webhook` отвечает 403. Неверный формат - ошибка при старте. См. [bot.md](bot.md). |
| `MAX_BOT_USERNAME` | нет | из `GET /me` | Username бота без `@` для кнопки открытия мини-приложения. Пусто - берётся из `GET /me` и кэшируется. |
| `PUBLIC_URL` (или `MINIAPP_URL`) | для бота | пусто | Публичный адрес приложения. Webhook регистрируется на `<PUBLIC_URL>/api/max/webhook`; на него же ведёт ссылка, если username бота определить не удалось. Если пусто и username неизвестен, бот присылает текст без кнопки. Скрипты деплоя добавляют `PUBLIC_URL=https://<домен>` в `.env`, если его нет. |
| `MAX_API_BASE` | нет | `https://platform-api2.max.ru` | Адрес API MAX (только `https://`). Единственный источник адреса, куда бот шлёт запросы. |
| `MAX_CA_BUNDLE` | нет | пусто | Путь к PEM-файлу доверенных сертификатов, если в системе нет сертификата Минцифры (см. [bot.md](bot.md)). |
| `BOT_REPLY_INTERVAL` | нет | `60` | Не чаще одного ответа на сообщения в личном чате за столько секунд на пользователя. |
| `BOT_NOTIFICATIONS_ENABLED` | нет | `1` | `1` — отправлять уведомления в личный чат MAX при проверке и сдаче заданий; `0` — полностью отключить уведомления. |
| `BOT_CHAT_COMMANDS` | нет | `1` | `1` — обрабатывать текстовые команды `/status`, `/tasks`, `/help` в чате; `0` — отвечать на все входящие сообщения только стандартной подсказкой с кнопкой приложения. |
| `INIT_DATA_MAX_AGE` | нет | `86400` | Максимальный возраст `auth_date` в секундах (сутки). Допустимо 60-86400, иначе ошибка при старте. Нечисловое значение молча заменяется на 86400. |
| `TEACHER_MAX_IDS` | нет | пусто | MAX id через запятую. Пользователь с таким id получает роль педагога (повышение роли). |
| `DIRECTOR_MAX_IDS` | нет | пусто | MAX id через запятую. Роль директора. Работает как запасной путь, см. [setup-school.md](setup-school.md). |
| `DEFAULT_CLASS_ID` | нет | `1` в `demo`, иначе не задан | id класса, в который сразу попадает новый пользователь. `0` или пусто - отключено. В `sandbox` всегда отключено. Если класса с таким id нет, при старте пишется предупреждение и значение отключается. |
| `CATALOG_FILE` | нет | `<DATA_DIR>/catalog.json` | Путь к необязательному каталогу школ (`prod`). Нет файла - каталог не применяется. Формат: `catalog.example.json`. |
| `SCHOOL_APPROVAL` | нет | `auto` | `auto` - новая школа активна сразу; `manual` - создаётся в статусе `pending` до подтверждения администратором платформы. Другое значение - ошибка при старте. |
| `PLATFORM_ADMIN_MAX_IDS` | нет | пусто | MAX id администраторов платформы через запятую. Эти администраторы не снимаются из интерфейса. Другие администраторы назначаются во вкладке «Люди» (`users.platform_admin`). |
| `BOOTSTRAP_FIRST_ADMIN` | нет | `1` | Только `prod`: первый пользователь MAX, вошедший в базу без единого пользователя и при пустом `PLATFORM_ADMIN_MAX_IDS`, становится администратором платформы (`users.platform_admin=1`), в журнал пишется предупреждение. `0` - выключить. Риск: если первым откроет приложение посторонний, он станет администратором. |
| `PLATFORM_ADMIN_CLIENT_IDS` | нет | пусто | Только `sandbox`: значения `X-Client-Id` администраторов платформы через запятую. В других режимах игнорируется. |
| `SANDBOX_WIPE` | нет | `0` | Только `sandbox`: `1`/`true`/`yes`/`on` - стереть базу при старте. По умолчанию база сохраняется; `npm run sandbox-wipe` включает это. |
| `DATA_DIR` | нет | `<корень проекта>/data` | Каталог данных. От него считаются база и каталог по умолчанию. |
| `DATABASE_PATH` | нет | `<DATA_DIR>/<имя базы>` | Полный путь к файлу SQLite. Перекрывает имя базы по режиму. Исключение: в `demo`/`sandbox` путь с именем боевой базы `school_hero.db` (например, значение по умолчанию из Docker-образа) заменяется на `school_hero_demo.db`/`school_hero_sandbox.db` в том же каталоге. |
| `ALLOW_PUBLIC_DEMO` | нет | `0` | Только `demo`: `1` разрешает `HOST` не на loopback (публичная витрина, например профиль `demo` в docker-compose). Без него `demo` стартует только на `127.0.0.1`, `localhost`, `::1`. |
| `STATIC_DIR` | нет | `<корень проекта>/static` | Каталог со сборкой фронтенда. |
| `SERVE_FRONTEND` | нет | `false` | `1`, `true`, `yes`, `on` (регистр не важен) - отдавать собранный фронтенд с корня. При `false` `GET /` возвращает JSON-заглушку со ссылками. |
| `HOST` | нет | `127.0.0.1` | Адрес привязки `python app.py` (берётся из проверенных настроек, `validate()` вызывается до запуска uvicorn); в `sandbox` проверяется на loopback, в `demo` - тоже, если нет `ALLOW_PUBLIC_DEMO=1`. Запуск `uvicorn app:app --host ...` напрямую обходит эту проверку и для `demo`/`sandbox` не поддерживается. |
| `PORT` | нет | `8000` | Порт `python app.py`. Читается напрямую из окружения; нечисловое значение - исключение при запуске. `tools/run_sandbox.py` подставляет `8010`. |

`bool`-переменные: значения, не входящие в `1/true/yes/on`, считаются `false`. Списки id: разделитель запятая, пробелы обрезаются, пустые элементы отбрасываются.

`.env.example` перечисляет не все переменные: в нём нет `DATA_DIR`, `DATABASE_PATH`, `STATIC_DIR`, `SANDBOX_WIPE`, `PLATFORM_ADMIN_CLIENT_IDS`.

## Что не настраивается через окружение

- Лимит школ на пользователя (3) - поле `max_schools_per_user` в `Settings`, из окружения не читается.
- Лимиты регистрации (60 классов в школе, 5 созданий школы в час, 20 неверных кодов за 10 минут) - константы в `backend/registration.py`.
- Часовой пояс: фиксированный UTC+3 (Москва) в `backend/game.py`. Неделя начинается в понедельник 00:00 по этому смещению.
- Порог рейтингов (100) - `LEADERBOARD_CAP` в `backend/service.py`.

## Пути данных

| Что | Где (по умолчанию) | В production (systemd) | В Docker |
| --- | --- | --- | --- |
| База SQLite | `data/school_hero.db` (+ `-wal`, `-shm`) | `/opt/school-hero/data/school_hero.db` | `/data/school_hero.db` (том `school_hero_data`) |
| Каталог школ | `data/catalog.json` | `/opt/school-hero/data/catalog.json` | `/data/catalog.json` |
| Сборка фронтенда | `static/` | `/opt/school-hero/static` | `/app/static` (собирается в образе) |
| Страница-портал | `landing/` | `/opt/school-hero/landing` | не копируется в образ, `/portal` вернёт 404 |

Файлы `data/*.db`, `-shm`, `-wal`, `static/`, `.env` исключены из git (`.gitignore`).

## Проверки при старте

`Settings.validate()` вызывается в `lifespan` приложения и завершает запуск с ошибкой, если:

- `APP_MODE` не из трёх допустимых;
- `APP_MODE=sandbox` и `HOST` не loopback;
- `APP_MODE=demo`, `HOST` не loopback и не задан `ALLOW_PUBLIC_DEMO=1`;
- `APP_MODE=demo`/`sandbox` и база с именем `school_hero.db` (боевая);
- `INIT_DATA_MAX_AGE` вне 60-86400;
- `MAX_WEBHOOK_SECRET` задан и короче 32 символов или содержит недопустимые символы;
- `SCHOOL_APPROVAL` не `auto`/`manual`;
- `APP_MODE=prod` и пустой `MAX_BOT_TOKEN`.

Если `catalog.json` существует, но повреждён (нет списка `schools`, нет `name`/`city`/`classes`, повторяется `invite_code`), старт тоже завершится ошибкой `CatalogError`.

## Приоритет значений

1. Переменные окружения процесса.
2. `.env` (через `python-dotenv`, не перезаписывает уже заданное).
3. Значения по умолчанию в коде.

Под systemd переменные из `EnvironmentFile=` по документации systemd перекрывают `Environment=` в юните. Поэтому `APP_MODE` в серверном `.env` важнее строки `Environment=APP_MODE=prod` в `deploy/school-hero.service`. В серверном `.env` должно быть `APP_MODE=prod`. В `docker-compose.yml` значения из `environment:` перекрывают `env_file`.

См. также: [deploy.md](deploy.md), [setup-school.md](setup-school.md).
